# 差速驱动机器人路径跟踪控制器（Pure Pursuit / Stanley）

给定参考路径与机器人当前位姿，计算跟踪路径所需的角速度（转向）控制量，
内置闭环仿真、失稳（横向误差发散）检测，并生成**单文件离线 HTML 报告**
逐帧回放运动过程与横向误差曲线。

- 仅依赖 Go 标准库（`math` / `encoding/json` / `html/template` 等）。
- 报告为单个静态 HTML，数据与逻辑全部内嵌，原生 HTML/CSS/Canvas/JS，
  无任何前端框架或图形库、无外部网络资源、无需启动服务，双击打开即可。

## 一、Pure Pursuit 的几何原理

每个控制周期：

1. 求机器人在路径上的最近投影点（弧长 `s*`）；
2. 沿路径向前取弧长 `s* + Ld` 处的点 `G` 作为前视点；
3. 计算机器人航向到视线 `robot→G` 的夹角 `α`；
4. 跟踪一个经过机器人与 `G`、与当前航向相切的圆弧，其曲率为

```
κ = 2 sin(α) / Ld
δ = atan(L · κ)          # 等效自行车模型前轮转角
ω = κ · v                # 差速底盘实际执行的角速度指令
```

**速度自适应前视**：`Ld = L0 + k·|v|`。高速时拉长前视、压低回路增益，
抑制切弯与振荡；低速时缩短前视以减小稳态横向误差。

### 终点处理（需求一）

当 `s* + Ld` 超过路径终点时，前视点被**夹到路径终点**而非外推：
此时曲率公式分母使用机器人到终点的**真实视线距离**（随接近连续缩短），
指令平滑衰减，机器人沿最小转弯圆弧驶向终点，不会产生转向突变或除零。

### 前视点跳变的处理（需求一）

自交叉路径（如 8 字）或大曲率急弯上，若每帧全局搜索“最近点”，
另一截几何上更近的路径会把跟踪点瞬间拽走，导致 `α`、`ω` 突变。
本实现用三道约束消除该问题：

1. **弧长窗口搜索**：只在上一帧投影弧长 `s*` 的前后 `SearchWindow`
   范围内找最近点，交叉的另一段路径天然落在窗口外；
2. **弧长单调**：投影弧长与前视弧长只允许沿路径前进方向增长，不允许回退；
3. **速度自适应前视**：避免高速下短前视造成的指令抖动。

## 二、Stanley 的几何原理

前轮转角律（车体原点为控制点）：

```
δ = kψ·ψ − atan(k·e / (|v| + ks))
ω = (v / L)·tan(δ)
```

- `ψ = wrap(pathHeading − θ)` 为航向误差；
- `e = cross(tangent, robot − nearest)` 为**带符号横向误差**：
  `e>0` 在路径左侧（需向右打舵），`e<0` 在右侧（需向左打舵），
  因此横向项取负号，与经典论文“路径在车体左侧 e 为正”的约定等价；
- `ks` 为软化项，防止 `v→0` 时 `atan(k·e/v)` 奇异。

### 角度环绕（需求二）

航向误差一律经 `AngleDiff = WrapPi(a−b)` 计算，结果落在 `(−π, π]`。
路径航向或机器人航向扫过 `±π` 接缝时，误差与 `δ` 保持连续，
不会出现 `2π` 的突跳（测试 `TestHeadingErrorWrapContinuity` 扫描验证）。

### 横向误差符号一致性（需求二）

`e` 由叉积定义，符号只取决于机器人位于路径切线的哪一侧。
机器人越过切点时，最近点沿路径移动但 `e` 的符号连续，
转向方向不会因为 `atan2` 包裹而翻转
（测试 `TestStanleyCrossTrackSign` 覆盖切点前后两侧）。

## 三、参数选择依据

### Pure Pursuit

- **基础前视 `L0`**：经验取 `0.3–0.8 m`（本项目速度量级 1–2 m/s）。
  太小 → 横向回路增益 `2v/Ld²` 过大，滞后存在时振荡发散；
  太大 → 大曲率处切弯、稳态误差增大。
- **速度增益 `k`**：取 `0.1–0.2 s`，让 `Ld` 随速度线性增长，
  维持 `v/Ld²` 量级稳定。
- **搜索窗口**：略大于 `Ld`（约 `1–2 m`），既能跟上急转弯，
  又能把自交叉的另一段排除在外。
- **轮距 `L`**：只影响 `δ` 的数值显示，不影响差速底盘执行的 `ω`。

### Stanley

- **横向增益 `k`**：直线可取 `1` 左右；曲率路径需要更大的 `k`
  以压低稳态误差（演示圆弧用 `k=2.5`）。过大会使横向回路失稳。
- **航向增益 `kψ`**：经典取 `1`。
- **软化项 `ks`**：取 `0.05–0.2 m/s`，保证低速/静止时增益有限。
- Stanley 对**曲率路径存在固有稳态偏移**（`ψ` 与横向项平衡所致），
  提高 `k`、降低速度可减小但无法完全消除，这是方法本身的几何性质。

### 仿真侧

- `SteerLagTau`：执行器/底盘一阶转向滞后时间常数。滞后引入相位延迟，
  是两种控制器在高增益下失稳的主要诱因；演示稳定场景取 0.05–0.06 s，
  失稳场景人为取 0.25–0.5 s。
- `MaxOmega` / `MaxSteer`：执行器限幅。限幅会把发散振荡“削”成
  大幅有界环，因此失稳演示中关闭限幅以暴露真实发散形态。

## 四、失稳判据（需求三）

检测器对每步横向误差的绝对值 `|e_k|` 做**快上慢下的单向指数平滑**
得到包络 `env`（贴合峰值，不被振荡谷值打断），在以下条件下判定发散：

1. **幅值门槛**：`env > AbsThreshold`（默认 0.8 m），排除小幅有界振荡；
2. 且满足任一：
   - **硬逃逸**：`env > HardEscape`（默认 3 m），立即确认；
   - **持续放大**：在 `ConfirmWindow`（默认 0.8 s）内包络单调走高
     （允许 2% 回撤噪声），且末端相对窗口最低点放大 `GrowthFactor`
     （默认 2.5）倍以上。

**发散开始时间步**定位为确认时刻向前回溯 `LookbackWindow`（默认 2.4 s）
内包络的**最低点（trough）**——即有界/收敛段与逃逸段的分界，
而不是阈值被穿越的确认时刻（二者之差为检测延迟，报告中同时给出
`divergeStep` 与 `confirmStep`）。

该判据把三种行为区分开：

- 收敛：包络持续下降；
- 有界振荡（含极限环、执行器限幅造成的大幅环）：包络不持续放大；
- 发散：包络越过幅值门槛并持续指数放大。

合成序列测试 `TestDivergenceDetectorOnSyntheticSeries` 用
“先有界振荡、第 200 步起指数逃逸”的序列验证起始步定位误差在 ±25 步内；
`TestBoundedOscillationNotFlagged` 与 `TestDivergenceDetectorBoundedSynthetic`
保证有界振荡不误报。

## 五、HTML 报告

`report` 包把所有场景的路径、逐帧位姿、控制量、横向误差序列与检测结论
序列化为 JSON，直接以内联 JS 对象字面量嵌入单个 HTML（`</` 转义为 `<\/`
防止脚本标签提前闭合）。页面包含：

- 场景标签页（可用 `#1`–`#8` 锚点直达）；
- Canvas 俯视图：参考路径、实际轨迹、机器人位姿三角、前视/瞄准连线、
  发散起点红叉；
- Canvas 横向误差时间曲线：零轴、发散区阴影与起始线、播放头、
  鼠标悬停十字线与数值提示；
- 播放 / 暂停 / 单帧步进 / 进度条 / 0.25×–4× 变速
  （键盘：空格、←、→）；
- 右侧状态面板：收敛结论、最大/末端误差、发散起始步与确认步。

支持系统深 / 浅色模式自动切换。
